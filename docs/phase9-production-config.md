# Phase 10 configuration checklist (review only)

Phase 9 did not deploy or change Nova's working localhost OAuth configuration. Local development remains on `http://localhost:3001` (`corepack pnpm dev`). Before a production deployment, choose one canonical HTTPS app origin and review the current [Supabase redirect guidance](https://supabase.com/docs/guides/auth/redirect-urls) and [Vercel environment variable guidance](https://vercel.com/docs/environment-variables).

**Phase 10 update:** The former Next attachment route was removed. Browser uploads now go directly to Supabase Storage and the Supabase `finalize-attachments` Edge Function inspects bytes before service-only finalization. This removes the [4.5 MB Vercel Function request-body blocker](https://vercel.com/docs/functions/limitations#request-body-size). See the current [Phase 10 deployment guide](phase10-deployment.md) for the launch steps and verification status.

1. On Vercel, set `NEXT_PUBLIC_SUPABASE_URL` to Nova's HTTPS project URL and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` to its public key for the intended environment. The app requires only these two environment variables. Never put a `service_role`, `sb_secret_...`, database password, Edge Function token, or GitHub client secret in Vercel browser variables. The private cleanup token remains in Supabase Vault/Edge Function configuration.
2. In Supabase Auth → URL Configuration, set **Site URL** to the canonical HTTPS production origin and add its exact `https://YOUR-DOMAIN/auth/callback` to **Redirect URLs**. Retain the exact `http://localhost:3001/auth/callback` development entry. Avoid broad production wildcards. If using a preview domain, add its exact callback separately and test it before sharing.
3. In GitHub OAuth App settings, set the homepage to the canonical app origin. Keep **Authorization callback URL** pointed at Supabase's `https://PROJECT-REF.supabase.co/auth/v1/callback`, not the app route. Keep its secret only in Supabase Auth provider settings.
4. Verify `getSupabaseConfig` accepts only HTTPS remote URLs; the SSR proxy refreshes cookies and adds `Cache-Control: private, no-store` to protected responses. The callback uses PKCE code exchange and clears its short-lived next-path cookie. Review HTTPS cookie behavior on the actual domain and repeat signed-out/protected-route tests.
5. Confirm private Realtime channels remain required, the `conversation-attachments` bucket is private, the cleanup Edge Function and hourly Cron job target the intended project, and RLS/grants/advisors are clean enough for the pilot. Migration `20260925010400_phase7_nova_cleanup_schedule.sql` contains Nova's project URL; a different project needs a reviewed additive schedule migration.
6. Run a preview build and signed-in smoke test. Do not point the live domain at the deployment until backup/restore and rollback steps are rehearsed. Vercel Hobby is for personal/non-commercial use; choose an eligible plan or host if the beta is commercial.

No Vercel project, domain, environment variable, or production Auth URL was changed in Phase 9.
