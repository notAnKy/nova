# Phase 9 signed-in walkthrough

Use two real workspace members and a third workspace admin who is outside one private conversation. Test one desktop keyboard, a phone or browser viewport at 320/375/390/430 px, a tablet width, and desktop. Record browser/OS and any failing step. Automated checks do not substitute for this walkthrough.

1. **Keyboard and focus:** Sign in and tab through workspace rail, switcher, sidebar, channel/DM list, composer, message actions, reaction picker, mention suggestions, thread panel, search, Activity, project forms, and settings. Verify visible focus, sensible order, labels, Enter/Space, Escape dismissal, and focus return. Test the skip-to-content link. Open/close the mobile drawer by keyboard and confirm its hidden controls do not receive focus. Repeat with reduced motion and a screen reader if available.
2. **Responsive:** At each width, open navigation, channels, a DM, the composer with three chosen files, inline attachment previews, mention picker, full-screen thread, reactions, search results, Activity, projects/tasks/decisions, and workspace settings. Check no horizontal overflow or clipped action, readable text, and usable touch targets. Raise/lower the mobile keyboard and confirm the composer stays reachable.
3. **Messaging/access:** Both DM participants can open and send; a workspace admin outside that DM cannot. Private-channel members can read and an outsider cannot. Verify a removed member loses fresh page/API/Storage access. Reconnect a tab and confirm missed durable messages, reactions, and Activity reload. A currently open Realtime socket may retain cached channel authorization until reconnect; durable reads and writes must still fail immediately.
4. **Mentions, threads, search, Activity:** Pick a mention by keyboard, send a reply, react, search for a public/private/DM message, and jump to a root and thread reply. Check source labels and timestamps. Mark Activity read and browse older pages. Deleted or inaccessible sources must not reveal snippets or counts to an outsider.
5. **Files:** Upload a valid small image and text file, preview and download before expiry, check the local-time expiration hint, and verify an expired attachment shows a placeholder while its message remains. A fresh Storage request to the old path must fail; the hourly worker should remove its object. Test failed/abandoned upload and deletion cleanup without modifying production users' data unexpectedly.
6. **Projects:** Create a project, task, assignment and decision; follow a source-message link. Move through task pages, decision pages, project Activity pages, and the project list. Change task status; archived projects remain readable and reject new items. A former project creator who is now an ordinary member must not edit another member's task unless assigned. For a private source, an outsider sees only “Source message unavailable.”
7. **Failure states:** Try an invalid/expired invite, deleted conversation URL, expired auth session, failed search/network, failed file upload, and Realtime disconnect/reconnect. Confirm human-readable errors with no raw SQL/table/function names. Retry where offered.

The prior Phase 8 signed-in flow was user-validated. The additional Phase 9 keyboard, width, pagination, failure, and restore checks above still need a real signed-in browser session.
